1f:T4e60,<p>The Flyweight design pattern is a structural design pattern commonly used when we want to group similar data for multiple objects. The primary intent of this pattern is to store common data for multiple objects in a single place and hence optimise for memory usage.</p>
<p>Let's understand this pattern by taking the case of a sneaker store 👟</p>
<h3>Sneaker Store</h3>
<p>Imagine running an online sneaker store. You've noticed that your customers always have a lot of questions and so, you've maintained every little detail about each pair of sneakers you have on display! 🗃</p>
<p>You have the following data points on <strong>every</strong> single pair:</p>
<ul>
<li>Name</li>
<li>Size</li>
<li>Color</li>
<li>Brand</li>
<li>Price</li>
<li>Materials Used</li>
<li>Description</li>
<li>Sample Image</li>
<li>laced</li>
</ul>
<p>You soon realized that for a given <em>type</em> of pair, you're storing the same information again and again. Take the case of the Nike Air Force 1. For any two pairs, the only thing different is the <code>size</code> and the <code>color</code>. Everything else is duplicate information 😱</p>
<p>This definitely isn't the best way to store the details because it's super memory intensive ad costly. To solve this problem, you decide to create an object to store all the <em>common</em> details of the shoe and store only the <code>size</code>, <code>color</code> and a reference to the "common object" with every shoe instance.</p>
<p>If all of this is confusing, don't worry. Taking a look at the code should make things easier 😉</p>

<span data-line=""><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8">}</span></span></code></pre></figure>
<p>Looking through the code written so far, we've created the details object for each type of shoe in our shop using a common struct. This way, we can add descriptions for more sneakers in the future 🤔</p>
<p>We've also created a map of the shoe type against the respective type. This way, every instance of the <code>Sneaker</code> struct can easily access the corresponding details.</p>
<p>Also notice that our <code>Sneaker</code> struct now only contains the <code>size</code>, <code>color</code> along with the <code>shoeType</code> that allows us to fetch it's other details.</p>
